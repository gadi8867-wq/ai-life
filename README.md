# AI Life 🌍

**AI Life** — браузерный persistent 3D-эксперимент с двумя автономными персонажами: **Альфой (OpenAI)** и **Бетой (Claude)**.

Идея проекта: человек не управляет персонажами и не выдаёт им сюжетные задания. Персонажи получают мир, базовые потребности, наблюдения, память и набор действий и должны самостоятельно принимать решения.

Текущая версия — **прототип интерфейса и локальной симуляции Alpha vs Beta**. Реальные вызовы OpenAI и Claude API пока не подключены.

## Что есть в текущем прототипе

### Мир и визуализация

- 3D-мир в браузере на Three.js.
- Земля, река, деревья, камни и трава.
- Костёр с простым визуальным эффектом.
- Освещение, тени и туман.
- Отображение реального времени и дня эксперимента.
- Простые человекоподобные 3D-модели Альфы и Беты.

### Alpha vs Beta

- Альфа обозначена как модель **OpenAI**.
- Бета обозначена как модель **Claude**.
- Персонажи находятся в одном мире и имеют одинаковую базовую структуру состояния.
- Интерфейс подготовлен под эксперимент с двумя разными модельными слотами.

**Важно:** названия OpenAI и Claude пока являются частью схемы эксперимента. Реальные LLM API в текущем `index.html` не вызываются.

### Локальная автономная логика

В текущей браузерной версии персонажи используют JavaScript-логику, а не LLM.

Прототип содержит базовые состояния и действия, включая:

- исследование;
- поиск воды;
- поиск еды;
- отдых;
- исследование деревьев и камней;
- перемещение по миру;
- работу с ресурсными узлами в рамках прототипной логики;
- память и счётчики событий/решений;
- взаимодействие персонажей.

Поэтому текущую версию **нельзя считать реальным сравнением OpenAI и Claude**.

### Интерфейс наблюдателя

- Кнопка **«Начать эксперимент»**.
- Фиксация времени старта через `localStorage`.
- Сохранение части состояния симуляции в `localStorage`.
- Пауза/продолжение.
- Следование камерой за Альфой или Бетой.
- Свободная камера.
- Автокамера.
- Панель метрик и событий.
- Speech bubbles.
- Локальная озвучка через браузерный `SpeechSynthesis`, если она поддерживается браузером.
- Адаптивный интерфейс для мобильных экранов.

## Локальный запуск

### Вариант 1 — открыть файл напрямую

Можно открыть `index.html` в современном браузере.

Однако для ES modules и предсказуемого поведения браузера рекомендуется использовать локальный HTTP-сервер.

### Вариант 2 — рекомендуемый локальный HTTP-сервер

#### Linux / macOS

```bash
cd ai-life
python3 -m http.server 8000
```

Затем открыть:

```text
http://localhost:8000
```

#### Windows

```powershell
cd ai-life
py -m http.server 8000
```

Затем открыть:

```text
http://localhost:8000
```

### Что требуется

- современный браузер с поддержкой WebGL и ES modules;
- интернет-соединение для загрузки Three.js с CDN;
- Python нужен только для запуска локального HTTP-сервера.

Three.js подключается непосредственно из CDN:

```text
https://cdn.jsdelivr.net/npm/three@0.180.0/build/three.module.js
```

## Как запустить эксперимент

1. Запустить `index.html` напрямую или через локальный HTTP-сервер.
2. Нажать **«Начать эксперимент»**.
3. Если эксперимент ещё не запускался, текущее реальное время будет записано как время старта.
4. Интерфейс начнёт показывать день эксперимента, состояния агентов, метрики и события.
5. Пользователь остаётся наблюдателем: управление камерой и пауза не являются командами персонажам.

Если данные предыдущего запуска сохранились в `localStorage`, прототип пытается продолжить его состояние.

## Ограничения текущей версии

Это прототип, а не законченная автономная AI-система.

### 1. Реальные модели пока не подключены

В коде определены модельные роли Alpha/Beta, но браузер сейчас **не отправляет решения персонажей в OpenAI API или Claude API**.

### 2. Решения пока не являются решениями LLM

Выбор действий выполняется локальной JavaScript-логикой и случайностью. Поэтому поведение текущей версии не является результатом работы двух независимых языковых моделей.

### 3. Persistent state пока ограничен

Состояние сохраняется через `localStorage`. Это подходит для прототипа, но не является надёжным backend-хранилищем для эксперимента длительностью месяцы или годы.

Пока нет:

- серверной базы данных;
- серверного журнала событий;
- резервного копирования состояния;
- отдельного постоянно работающего simulation worker;
- гарантированной непрерывной работы при закрытой вкладке.

### 4. Мир упрощён

Текущая геометрия и поведение ресурсов упрощены. Полноценной физики, сложной экономики, производства, инвентаря и многоэтапного строительства пока нет.

### 5. Взаимодействия и диалоги прототипные

Текущие разговоры и социальные события не являются свободным долгосрочным общением двух независимых LLM с полной историей опыта.

### 6. Twitch/OBS пока не интегрирован как отдельная production-система

Визуальная сцена уже рассчитана на наблюдение и потенциальный 24/7 stream, но полноценного Twitch API/чат-интеграции и отдельного production Stream Mode пока нет.

### 7. SpeechSynthesis зависит от браузера

Озвучка использует встроенный API браузера и может работать по-разному на разных устройствах. Некоторые мобильные браузеры требуют пользовательского жеста перед синтезом речи.

## Принципы будущего эксперимента

Чтобы сравнение моделей было содержательным, различие между Alpha и Beta должно быть максимально ограничено самой моделью.

Обе стороны должны получать одинаковые:

- мир и физические правила;
- начальные условия;
- потребности;
- органы чувств и формат наблюдений;
- структуру памяти и её ограничения;
- доступные действия;
- лимит контекста и бюджет решений;
- игровое время;
- опасности и ресурсы;
- формат входных данных;
- формат выходных решений.

Агенты не должны получать заранее поставленные цели вроде «найди второго агента», «построй дом» или «подружись». Человек также не должен передавать им подсказки или информацию о существовании другого агента.

Для воспроизводимого сравнения желательно использовать одинаковые seed и условия старта и проводить несколько независимых запусков. Один запуск сам по себе не доказывает превосходство одной модели над другой.

## Следующий шаг: подключение реальных моделей

Следующий технический этап — вынести принятие решений из браузерного JavaScript в отдельный **AI runtime/backend**.

Рекомендуемая схема:

```text
                  ┌─────────────────────┐
                  │      3D Browser      │
                  │   Three.js / UI     │
                  └──────────┬──────────┘
                             │
                     observations/actions
                             │
                  ┌──────────▼──────────┐
                  │    Simulation Core  │
                  │ world + needs +     │
                  │ memory + rules      │
                  └───────┬───────┬──────┘
                          │       │
                    same input   same input
                          │       │
                ┌─────────▼─┐   ┌─▼─────────┐
                │   Alpha   │   │   Beta    │
                │  OpenAI   │   │  Claude   │
                └───────────┘   └───────────┘
```

### Минимальная архитектура следующего этапа

1. **Simulation Core** — единственный источник истины для мира, времени, ресурсов, здоровья, позиций и последствий действий.
2. **Observation Builder** — формирует одинаковое наблюдение для обоих агентов.
3. **Memory Store** — хранит опыт каждого агента отдельно.
4. **Decision Gateway** — принимает запрос на решение и направляет его в нужный model provider.
5. **Strict Action Schema** — модель может вернуть только допустимое действие из заранее определённого набора.
6. **Action Validator** — проверяет действие до применения к миру.
7. **Event Logger** — записывает `observation → decision → action → result`.
8. **Persistent Database** — сохраняет состояние мира и журнал независимо от браузерной вкладки.

### Безопасность API-ключей

API-ключи OpenAI/Claude **нельзя помещать непосредственно в `index.html`** или другой клиентский JavaScript, который отдаётся браузеру.

Браузер должен обращаться к собственному backend/API gateway, а секретные ключи должны храниться на серверной стороне в переменных окружения или другом защищённом хранилище.

## Формат решения агента

На следующем этапе обе модели желательно подключить к одному и тому же строгому формату ответа, например:

```json
{
  "action": "move",
  "target": {
    "x": 12,
    "z": -8
  }
}
```

Опциональные текстовые поля для наблюдаемого журнала можно хранить отдельно. Не следует пытаться получать или сохранять скрытую цепочку рассуждений модели.

Движок должен проверить `action` и `target`, а только затем применить действие к миру.

## Долгосрочная цель

AI Life должен превратиться из браузерного прототипа в persistent-наблюдение за двумя независимыми агентами, которые:

- сами исследуют мир;
- самостоятельно заботятся о базовых потребностях;
- учатся на последствиях действий;
- запоминают опыт;
- встречают друг друга без заранее выданной цели;
- постепенно формируют социальное поведение;
- могут добывать ресурсы, строить и изменять окружение;
- продолжают существовать независимо от того, наблюдает ли человек прямо сейчас.

Главный эксперимент — не заставить агентов выполнить заранее написанный сценарий, а создать одинаковые условия и наблюдать, какое поведение возникает из их взаимодействия с миром.

## Статус

**Текущий статус: Prototype / Alpha vs Beta UI + local simulation.**

Реальные OpenAI/Claude API, полноценный backend, надёжное многомесячное persistent-хранилище и production-ready 24/7 runtime являются следующими этапами разработки.
